# FPLL CPU optimizations — what they do and how they were validated

Two opt-in knobs cut the live ATSC decode CPU on x86 with **no change to picture
quality**. Both are enabled by default in `tools/stvt_run.sh`:

| Knob | Saving | Quality |
|---|---|---|
| `STVT_FPLL_FOLD=1` | ~6% total CPU | **bit-exact** (identical output bytes) |
| `STVT_FPLL_BLOCK_NCO=1` | ~6–8% more, additive | decode-identical (within RS run-noise) |
| both | **~12–14% off live decode** | indistinguishable |

## What they actually change

The frequency/phase-locked loop (`atsc_fpll_tight`) recovers the 8-VSB carrier — a
sequential, per-sample feedback loop running at the input sample rate. It's one of
the live throughput bottlenecks, so shaving work here directly lowers CPU.

- **`STVT_FPLL_FOLD`** folds the `dc_blocker_ff` and `agc_ff` stages into the FPLL's
  own output loop using flat ring buffers, so three GNU Radio blocks become one
  pass. It is a *bit-exact* replica — the output is byte-for-byte identical to the
  unfolded chain.

- **`STVT_FPLL_BLOCK_NCO`** processes the carrier loop in blocks of N samples
  (`STVT_FPLL_BLOCK_LEN`, default 16). Within a block the NCO mixer is generated by a
  complex-rotation **recurrence** (`c *= w`) instead of a `sincosf` per sample, and
  the phase detector + loop filter run **once per block** (one `fast_atan2f` instead
  of N). Corrections are scaled by N (`alpha*x*N`, `beta*x*N`) so the average loop
  gain — hence loop bandwidth and acquisition speed — is preserved. The phasor is
  re-seeded from the exact NCO phase each block so float drift can't accumulate. Not
  bit-exact, but decode-identical in practice.

Both flags are read by `getenv()` inside the C++ `work()`, so they apply to live
decode and the deterministic replay harness identically, with no Python wiring. The
per-sample default path is unchanged when the flags are off.

## Validation

Measured on a Ryzen 1600X (6-core), production live config (`STVT_RS=stock`,
`STVT_VITERBI=hard`, `STVT_EQ=long`, `STVT_SPS=1.1`, `STVT_RRC_SYMS=4`).

### 1. Deterministic A/B (identical input bytes → isolates the algorithm)

75-second marginal RF34 capture, replayed through `tools/tv_replay.py`, 2 trials,
CPU = User+System seconds:

| Config | CPU (User+Sys) | vs old | tei% / top video PID |
|---|---|---|---|
| old (both off) | 324.8 s | — | 2.41% / 30.72% |
| fold only | 295.3 s | **−9.1%** | 2.41% / 30.72% (bit-identical) |
| fold + block-NCO | 265.5 s | **−18.3%** | 2.42% / 30.72% |

Block-NCO's only deviation was ~85 RS-failed packets out of 967,116 (0.009%) — pure
run-noise — with a bit-identical video-PID share.

### 2. Live soak (real RF, 4 min steady-state each)

| Config | Chain CPU | Data rate | Lock `mean\|x\|` | Overflows |
|---|---|---|---|---|
| old (both off) | 461% | 2.31 MB/s | 0.035–0.038 | 0 |
| fold + block-NCO | **403%** | 2.31 MB/s | 0.035–0.038 | 0 |

Identical lock and throughput for **−12.6% live CPU** (~0.58 of a core, continuously).

### 3. Endurance (10 hours, all channels)

A headless harness cycled scanner → 9-minute live soak on every decodable channel →
surfer retune, for 10 hours (15 cycles). Result: **zero overflows, zero chain
deaths, zero SDR wedges** across ~60 nine-minute soaks; the surfer re-acquired every
channel in 3 s on every pass. The shipped config held a stable lock the entire run.

## Reverting / A-B testing

Set either knob to `0` to disable it (`STVT_FPLL_BLOCK_NCO=0` reverts to the
per-sample carrier loop; `STVT_FPLL_FOLD=0` restores the separate dc-blocker/AGC
blocks). `STVT_FPLL_BLOCK_LEN` tunes the block size (2–256, default 16); larger
saves more trig but tracks slightly looser.
